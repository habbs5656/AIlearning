# SRCNN 常用术语表

> 整理于 2026-10-29。按「数据 → 网络 → 打分 → 训练 → 实验方法」五组排列，
> 每条给一句类比 + 在本项目里的具体所指。回看报告或跟导师汇报前扫一遍即可。

## 一、任务与数据（图从哪来）

| 术语 | 英文 | 一句话解释 | 本项目对应 |
| --- | --- | --- | --- |
| 超分辨率 | Super-Resolution, SR | 把模糊图变清晰。注意**尺寸不变**，变的是清晰度 | 输入糊的 96×96，输出清楚的 96×96 |
| HR | High Resolution | 清晰原图，充当标准答案 | 真实照片切出的 96×96 块 |
| LR | Low Resolution | 网络的输入，糊的那张 | HR 缩小 3 倍再放大回来 |
| 退化 | Degradation | 把 HR 变成 LR 的过程，决定任务难度 | `dataset.py::degrade`，用 bicubic 缩小再放大 |
| 双三次插值 | bicubic | 取周围 16 个像素加权平均算新像素。**只能抹平，不能创造细节** | 既是退化的手段，也是基线 |
| 放大倍数 | scale | 缩小多少倍再放大回来 | 3（96 → 32 → 96） |
| 图像块 | patch | 从大图裁出的小方块，一个 patch 就是一个训练样本 | 96×96，每张图裁 100 块 |
| 训练集 / 验证集 | train / eval | 练习册 / 考卷。考卷上的图模型**从没见过** | 200 张 / 5 张 |
| 数据增强 | augmentation | 随机翻转、裁剪，让有限数据变多 | `dataset.py` 里 `random.random() < 0.5` 那段 |
| 采样噪声 | sampling noise | 验证集太小导致的分数不稳，**与种子无关** | 只有 5 张验证图，换一批可能差 0.3 dB |
| BSDS | Berkeley Segmentation Dataset | 超分论文的通用数据集 | 本项目只取了其中 200 张，规模远小于论文 |

## 二、网络结构（内部怎么算）

| 术语 | 英文 | 一句话解释 | 本项目对应 |
| --- | --- | --- | --- |
| 卷积 | Convolution | 小窗口在图上滑动，每停一次算一个数 | 类比拿放大镜逐块扫，记录「这块像不像边缘」 |
| 卷积核 | kernel / filter | 那个小窗口的尺寸 | 9×9、5×5、5×5（实验 B 改这个） |
| 感受野 | receptive field | 一个输出像素「看到」的输入范围。层越深越大 | 第一层 9×9，三层叠加后约 21×21 |
| 通道 | channel | 同一位置并行做几组卷积，得到几张特征图 | 3 → 64 → 32 → 3 |
| 特征图 | feature map | 每层的输出，可理解为「检查结果」 | 64 张 = 用 64 种窗口各扫一遍 |
| 补边 | padding | 在图像边缘补 0，保证输出尺寸不变 | `padding=4`，配合 9×9 让 96 进 96 出 |
| ReLU | Rectified Linear Unit | `max(0, x)`，负数归零，正数不变 | 引入非线性；没有它多层卷积等价于一层 |
| 参数 / 权重 | parameter / weight | 网络里可调的数字总数 | 约 6 万（`model.py` 自检会打印） |
| 前向传播 | forward | 输入 → 逐层算 → 输出 | `model(x)` |
| 反向传播 | backward | 根据误差反推每个权重该往哪调 | `loss.backward()`，由 PyTorch 自动完成 |
| 跳跃连接 / 残差 | skip / residual | 把输入直接加到输出上，只学「要改的部分」 | 原版 SRCNN 没有（实验 D 的变量） |
| 深度 | depth | 卷积层数 | 3 层（实验 C 改这个） |

## 三、评价指标（分数怎么算）

| 术语 | 英文 | 一句话解释 | 本项目对应 |
| --- | --- | --- | --- |
| PSNR | Peak Signal-to-Noise Ratio | 逐像素比较 SR 与 HR，差距越小分越高 | 现在 30.11 dB |
| MSE | Mean Squared Error | 像素差的平方再取平均，PSNR 由它换算 | `utils.py::psnr` 里那行 `np.mean(...**2)` |
| 分贝 | dB | 对数刻度，**每 +3 dB 约等于误差减半** | 30.11 vs 29.08 差 1 dB ≈ 误差少 20% |
| Y 通道 / 亮度 | luma | RGB 三色里的明暗信息，人眼最敏感 | 改完后分数从 28.9 跳到 29.7，是换尺子不是变强 |
| BT.601 | — | 亮度公式 `0.299R + 0.587G + 0.114B` 的来源标准 | `utils.py::rgb_to_y` |
| 基线 | baseline | 完全不训练也能达到的水平 | bicubic 直接输出 = 29.08 dB |
| 净增益 | gain | 模型减基线 | `+1.03 vs bicubic`，这才是网络的真实贡献 |
| 当前最优 | SOTA (State of the Art) | 该任务已知最好水平 | SRCNN 论文在 Set5 上报 32.75 |

## 四、训练过程（代码跑起来在做什么）

| 术语 | 英文 | 一句话解释 | 本项目对应 |
| --- | --- | --- | --- |
| 轮 | epoch | 把全部训练数据完整过一遍 | `--epochs 3` |
| 批 | batch | 一次喂几个样本，再统一更新权重 | 16 |
| 迭代 / 步 | iteration / step | 更新一次权重 | 20000 ÷ 16 ≈ 1250 步/轮 |
| 损失 | loss | 这一轮「错得有多离谱」 | `0.005770 → 0.003247 → 0.003106`，在降就是学着了 |
| 学习率 | learning rate, lr | 每次调权重的步长 | 1e-4。太大跳过最优点，太小 100 轮也学不完 |
| 优化器 | optimizer | 决定「怎么根据 loss 调权重」的算法 | 默认 Adam（实验 E 的变量） |
| SGD | Stochastic Gradient Descent | 只看当前坡度，最朴素 | — |
| Adam / AdamW | — | 记历史梯度、自动调步长，通常更快收敛 | AdamW 是其改进版（解耦权重衰减） |
| 超参数 | hyperparameter | **你自己定的**数字，不是网络学出来的 | lr、batch、层数、核大小、epoch 数 |
| 随机种子 | seed | 随机数序列的起点，同种子必得同结果 | `--seed 42` |
| 确定性 | deterministic | 让 GPU 每次走同一条计算路径 | `torch.backends.cudnn.deterministic = True` |
| cuDNN | CUDA Deep Neural Network library | NVIDIA 的卷积加速库 | 非确定性就来自它的算法自动选择 |
| benchmark 模式 | — | cuDNN 实测挑「最快卷积算法」，但两次挑的可能不同 | 必须设 `False`，否则结果会飘 |
| 过拟合 | overfitting | 训练集分数很好、验证集很差 | 本项目 3 轮远未到这一步 |
| 泛化 | generalization | 在没见过的图上仍然表现好 | 验证集存在的意义 |

## 五、实验方法（怎么让结论站得住）

| 术语 | 英文 | 一句话解释 | 为什么重要 |
| --- | --- | --- | --- |
| 控制变量 | controlled variable | 一次只改一个因素，其余全部锁死 | 否则分不清是哪个改动带来的效果 |
| 消融实验 | ablation study | 逐个替换或去掉某个组件，看指标变化 | 实验 B~E 本质都是消融 |
| 噪声 | noise | 同一配置重复测量时的波动 | 原来约 0.08 dB，固定种子后为 0 |
| 标准差 | standard deviation | 波动的量化指标 | 原来约 0.04 dB，就是「你的尺子晃多少」 |
| 信噪比 | SNR | 信号 ÷ 噪声。< 1 时实验设计失效 | 0.08 噪声 vs 0.05 信号 → 测不出来 |
| 可复现性 | reproducibility | 别人按你的步骤能得到同一个数 | 论文的基本要求，也是导师最先问的 |

## 最容易搞混的五对

**1. HR vs LR**
两者**尺寸相同**（都是 96×96），差别在清晰度。不是「大图和小图」的关系。

**2. bicubic 基线 vs 模型输出**
基线是把 LR 原样当答案交上去，分数 29.08。模型输出 30.11。**只有差值 +1.03 属于网络的功劳。**

**3. 参数 vs 超参数**
参数是网络自己学的（6 万个权重）；超参数是你定的（lr、层数）。导师问「超参数怎么选的」，问的是你为什么定这些数字。

**4. 卷积核大小 vs 感受野**
卷积核是第一层的窗口（9×9）。感受野是最终输出一个像素能看到多大范围，是逐层累加的（三层约 21×21）。**核变小会让感受野变小，但两者不等。**

**5. 种子噪声 vs 采样噪声**
种子噪声 = 同一个模型重跑分数不同 → 固定种子可消除。
采样噪声 = 换一批验证图分数不同 → 只能扩大验证集。
**固定种子解决了前者，对后者无效。** 这是实验 A 要单独回答的问题。

## 自测（先自己想，再看答案）

1. 为什么 PSNR 从 28.9 变成 29.7，不能说是模型变强了？
2. 30.11 和 32.75 差 2.64 dB，这个比较公平吗？为什么？
3. `loss` 从 0.005770 降到 0.003106，说明什么？降到 0 意味着什么？
4. 把 `num_workers` 从 4 改成 0 是为了什么？
5. 为什么 `set_seed()` 必须在建模型**之前**调用？
6. 实验 B 只改卷积核大小，其余参数为什么一个都不能动？
7. 5 张验证图算出的 30.11，和 100 张算出的 30.11，哪个更可信？
8. 你的 bicubic 基线是 29.08，如果换一批验证图变成 28.60，说明了什么？

<details>
<summary>参考答案</summary>

1. 因为同时换了评价尺子（RGB → Y 通道），分数上升来自指标变化，不是模型能力变化。看能力要看 `vs bicubic` 的差值。
2. 不公平。数据集规模（200 张 vs 数十万）、训练时长（3 轮 vs 几十万轮）、评测集都不同。只适合做「我们和 SOTA 还有多远」的粗略参考。
3. 说明模型还在学习，远未收敛。降到 0 意味着在训练集上完全拟合，通常已经过拟合，验证集分数反而会下降。
4. 多进程读数据会引入无法控制的随机顺序，破坏可复现性。单进程才能保证每次的数据顺序完全一致。
5. 种子必须在**任何随机操作发生前**设置。模型初始化本身就是随机的，先建模型再设种子，权重已经是随机的了。
6. 控制变量。同时改两个因素，就分不清分数变化来自哪个。
7. 100 张更可信。样本越多，平均值越接近真实水平，采样噪声越小。
8. 说明基线本身也受采样噪声影响，5 张图的代表性不足。这会直接威胁实验结论，应该扩大验证集。

</details>
